# ACP Bridge Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement the ACP bridge per `2026-07-17-acp-bridge-design.md` (revised 2026-07-23): a new `github.com/looprig/acp` module (protocol + stdio transport + agent facade + client), the foreignloops prerequisites (`LoopIdle` emission, typed stop reasons, optional agent shutdown), and `foreignloops/driver/acp`.

**Architecture:** Three-layer bridge. `acp/protocol` + `acp/transport/stdio` are a stdlib-only JSON-RPC/ACP wire layer with generated types from a pinned upstream schema artifact. `acp/agent` exposes a Looprig product as an ACP agent through consumer-owned host interfaces (never importing product code). `acp/client` + `foreignloops/driver/acp` drive a foreign ACP agent as a normal foreign loop; only `foreignloops/backend` mints Harness events. Harness itself is never touched except where this plan explicitly says so (it isn't — Phase 0 touches only foreignloops).

**Tech Stack:** Go 1.26 stdlib only (encoding/json, os/exec, bufio, context, sync). Dev tools: gosec, govulncheck, staticcheck (same as harness/foreignloops). No external ACP SDK — types are generated by an in-repo generator from pinned schema JSON.

- Commit messages: conventional style, **no Co-Authored-By trailer** (repo convention).

### Task 1.5: Connection dispatcher

**Files:**
- Create: `acp/protocol/conn.go`
- Test: `acp/protocol/conn_test.go` (drive both ends over `net.Pipe`/`io.Pipe`)

**The contract (write this exactly):**

```go
// Conn is one bidirectional JSON-RPC connection. It routes incoming requests to
// registered handlers and correlates outgoing requests with their responses.
type Conn struct{ /* ... */ }

type HandlerFunc func(ctx context.Context, method string, params json.RawMessage) (any, error)

func NewConn(r io.Reader, w io.Writer, opts ConnOptions) *Conn
func (c *Conn) Handle(method string, h HandlerFunc)            // request handler
func (c *Conn) HandleNotify(method string, h NotifyFunc)       // notification handler
func (c *Conn) Call(ctx context.Context, method string, params, result any) error
func (c *Conn) Notify(ctx context.Context, method string, params any) error
func (c *Conn) Close() error
func (c *Conn) Done() <-chan struct{}
```

**Step 1: Failing tests, one behavior each:**
- request → registered handler → response with same id; unknown method → `MethodNotFound`.
- pending-request table: `Call` blocks until response; context cancel removes the pending entry (no leak — assert via exposed `pendingLen()` test hook or unexported access in white-box test).
- **fail-all on termination:** peer closes → every in-flight `Call` returns typed `*ConnClosedError`; subsequent `Call` fails fast.
- **disjoint id spaces:** ids minted by `Call` start at `1<<32`; `ConnOptions.ExtIDBase` path (used later for extension traffic) counts from 1; a test asserts no collision when both run concurrently.
- **buffered early notifications:** notifications for a method arriving before `HandleNotify` are buffered (bounded `NotifyBufferDepth = 512`, overflow drops oldest and increments a counter surfaced on `Close`); registering the handler flushes in order.
- concurrency cap: at most `MaxInFlightHandlers = 64` handler goroutines; excess requests queue.
- typed + catch-all extension passthrough: `HandleUnknownRequest` / `HandleUnknownNotify` hooks receive anything unrouted (used for `_meta`/vendor methods later).

**Step 2–5:** FAIL → implement → PASS (`-race`, with a goroutine-leak check: `t.Cleanup` asserting `runtime.NumGoroutine` returns to baseline within 1s) → commit `feat(protocol): connection dispatcher with pending table, id spaces, buffered notifications`.

### Task 5.1: `acp/client` connection runtime

**Files:**
- Create: `acp/client/client.go`, `acp/client/session.go`

Contract:

```go
type Client struct{ /* conn + proc + state */ }

func Dial(ctx context.Context, cmd stdio.Command, opts Options) (*Client, error) // spawn + start-once initialize
func (c *Client) NewSession(ctx context.Context, p NewSessionParams) (*Session, error)
func (c *Client) LoadSession(...); ResumeSession(...); Close(ctx) error

type Session struct{ /* id, update stream, prompt gate */ }
func (s *Session) Prompt(ctx context.Context, blocks []ContentBlock) (*PromptResult, error)
func (s *Session) Updates() <-chan Update   // typed, buffered-from-subscribe
func (s *Session) Cancel(ctx context.Context) error
```

Behaviors (TDD, mockpeer faults): start-once state machine (concurrent Dial-users share one attempt; failed start resets, retry works); one prompt in flight per session (semaphore), cancel → `session/cancel` notification + result `cancelled` without error; process death → all pending calls fail typed, `Updates` closes; buffered early updates (mockpeer streams before consumer subscribes — nothing dropped); replay-idle tolerance on load: replay updates consumed, load response awaited under `LoadTimeout = 90s`, hang → typed timeout (no synthesis); `_meta.eventId` dedup: highwater per session drops duplicate live updates, replay exempt. Injected client capabilities: `Options{FS FSHandler, Terminal TerminalHandler, Permissions PermissionHandler, Elicitation ElicitationHandler}` — nil ⇒ capability not advertised (matrix test); dispatcher validates every inbound path/id before invoking a handler. Commit per behavior cluster (3–4 commits).

Contract: implements `driver.Agent`.

```go
func NewAgent(parentEnv []string, cfg Config) (driver.Agent, error)
// Config: ExecPath (absolute), Args, EnvAllow, plus acp client Options limits.
```

Behaviors (TDD):
- Lazy persistent connection: first `Spawn` dials (start-once, `initialize` happens here — once per connection, never per turn); later `Spawn`s reuse. Agent implements `Shutdown(ctx)` (closes client + subprocess) — invoked by the Task 0.4 backend hook (integration-assert via tests module).
- `Turn.StartNew` → `session/new`, emit `KindInit{SessionID}` first (backend late-bind path). Not new → reuse session; if the process restarted since, `session/load` first (replay updates are **not** re-emitted as driver events — dedup via `_meta`/replay marking). If `StartNew` is false, a prior SID exists, and the foreign agent did **not** advertise `loadSession`, `Spawn` fails with a typed driver error (test this) — never silently start a fresh session under an old SID.
- Update mapping → `driver.Event`: message chunk → `KindTextDelta`; thought chunk → `KindThinkingDelta`; `tool_call` → `KindToolUse` (ACP tool call id → `ToolUseID`, title → `ToolName`); terminal `tool_call_update` → `KindToolResult` (+`IsError`); complete assistant turn content assembled → `KindStepComplete` with `*content.AIMessage`; plan updates: **dropped in v1** (no driver kind; documented limitation).
- Prompt result → terminal: `end_turn` → `KindTerminalOK/StopEndTurn`; `cancelled` → `KindTerminalOK/StopCancelled`; `refusal|max_tokens|max_turn_requests` → `KindTerminalError` with matching `StopReason`; transport/typed errors → `KindTerminalError/StopUnspecified` + `ErrText`.
- `Stream.Close()` cancels the prompt only (subprocess survives). `Stream.History()` → `{Available:false}`.
- Permission auto-responder from `Turn.Posture`: `PostureDefault` → reject-class option; `PostureAcceptEdits` → `allow_once`-class **only when the associated `tool_call.kind` is edit-class (edit/move/delete)**; execute/fetch/unknown kinds → reject even under AcceptEdits; **never** `allow_always` (table test over option sets × tool-call kinds, incl. adversarial: only-allow_always offered → reject; missing/unresolvable tool-call reference → reject).

Commit sequence: contract+mapping, connection lifecycle, permissions.
