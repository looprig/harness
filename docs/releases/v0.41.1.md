# v0.41.1

Fix plain-JSON hustle output extraction for reasoning models. A response may
contain non-nil thinking blocks alongside exactly one non-nil text block. Only
the text becomes the result; its original JSON bytes, byte limit, and usage
accounting are preserved. Thinking-only responses, multiple text blocks,
malformed blocks, tool calls, and empty, invalid, or oversized JSON remain errors.

Plain-JSON extraction now also refuses length-limited, content-filtered,
tool-use, and unrecognized finish reasons through the existing typed
`inference.StructuredOutputFinishError`. A stop response containing a tool call
is refused as well. Existing unknown-finish compatibility is retained.

Because a finish refusal carries the finish error rather than a shape reason,
compaction now journals `CompactRejectExecutionFailed` instead of
`CompactRejectInvalidSummary` for two responses: a stop finish that also carries
a tool call, and a length-truncated response whose text is invalid JSON. Control
flow is unchanged; only the recorded reject reason differs.

No public API, wire format, dependency pin, provider capability, or native
structured-output extraction changes. Consumers using a local workaround for
reasoning-plus-JSON output can adopt this patch before removing that workaround.
